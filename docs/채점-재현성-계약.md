# 채점 재현성 계약

기본 확인 기준은 `assets/rubrics/laimory-metric-v5.md`, 편집본은 `data/rubrics/<stageKey>.json`이다.
8개 단계·64개 항목·각 단계 100점 배점은 유지한다. 기본값의 세부 판정 기준은 총 194개다.

## 실제 요청과 계산

`stage_judge.default_rubric`은 기존 확인 기준 원문 뒤에 `assets/rubrics/calibration/rules.md`의
판정·환산 규칙, 항목별 기준 ID와 배점에 맞춘 환산 예시, 해당 단계의 합성 경계 예시를 붙인다.
설정에서 편집한 단계에는 현재 기준의 ID·환산 예시를 생성한다. 원본 전용 경계 예시는 넣지 않는다.

- 최상위 bullet 하나가 기준 하나이며 하위 bullet은 그 안의 조건이다.
- User Memory 고정 field 표는 데이터 행 하나가 기준 하나다.
- 자유문으로 편집된 기준은 전체가 기준 하나다.
- 설명·참조 표·별도 코드 측정 문장을 새로운 배점 기준으로 만들지 않는다.
- JSON Schema는 각 항목의 모든 기준 ID를 요구하고 추가 ID와 누락 ID를 거부한다.
- LLM은 `total`, `passed`, `failedRefs`, `reason`을 반환한다. 점수·applied는 반환하지 않는다.
- `0 ≤ passed ≤ total`, 실패 근거 개수 `= total-passed`, 근거 위치 중복 없음, 빈 이유 없음 조건을 검증한다.
- 각 기준의 `passed/total`을 동일 가중치로 평균하고 항목 배점을 곱한다. total=0인 기준은 제외한다.
- 유리수로 계산한 뒤 항목별로 한 번 정수 반올림(.5 이상 올림)한다. 전부 total=0이면 항목 N/A다.
- 총점과 N/A 배점 재분배는 기존 `stage_schema.tally`가 수행한다.
- severity·alerts는 별도 설명이며 추가 벌점을 만들지 않는다. 반올림으로 만점이어도 위반 기록은 유지한다.

## 결정론 검사 범위

현재 코드가 직접 계산하는 것은 기본 Question 기준의 coverage c01/c02 및 expression c02다.
입력 clientEventId에 질문이 정확히 하나 연결됐는지, 질문이 앞뒤 공백 제거 후 1~40자인지 확인한다.
한글·영문·공백·문장부호를 포함한 Unicode 문자 수이며 JSON 인코딩용 따옴표는 세지 않는다.
누락 질문은 실패로 남기며 알 수 없는 입력 형식·중복 입력 ID는 측정값을 추측하지 않는다.
확정 판정은 프롬프트와 화면에 제공하고, 모델 반환 후 코드 값으로 다시 확정한다.

events 블록의 JSON 배열 뒤에 자연어 지시가 있어도 선두 배열을 파싱할 수 있다.
원문은 그대로 보존한다. 한 줄짜리 JSON 배열을 `[events]` 같은 섹션 이름으로 오인하지 않는다.
Question 단계가 실행됐고 입력 event가 있으면 출력이 전부 비어도 N/A로 숨기지 않는다.

다른 단계의 의미 판정·건수 집계는 LLM이 수행한다. 모든 기존 '코드 측정' 항목이 구현된 것은 아니다.

## 저장·호환과 사용

기존 항목별 정수 score·applied·reason·총점 구조와 schemaVersion 2를 유지한다.
새 점수에는 `scoringPolicy: criteria-ratio-v1`, `checks`를 추가해 실제 판정을 보존한다.
오래된 결과는 다시 계산하지 않으며 기존 UI에서 계속 읽을 수 있다. 실제 프롬프트는 기존
`judge-stage-<stageKey>` 레지스트리에서 본문 변경에 따라 다음 채점 시 새 버전으로 저장한다.

설정 또는 Task 리뷰의 기준 편집 영역에서 '현재 채점 프롬프트 · 계산 규칙과 예시'를 펼치면
실제 저장된 기준의 프롬프트를 볼 수 있다. 채점 결과의 '세부 판정 건수와 근거 보기'에서 계산 근거를 확인한다.

환산 방식이 바뀌었으므로 이전 버전과 절대 점수를 그대로 비교하면 안 된다. 같은 데이터 묶음을
새 기준으로 재채점해 비교 기준을 다시 잡는다. 정수 반올림이나 점수 고정만으로 정확성을 보장하지 않는다.

## 반복 검증

`scripts/check_judge_repeatability.py`는 운영 평가 파일을 변경하지 않고 합성 보류 사례 2개를
고정 모델로 기존 Question v2와 개선 기준에 각각 반복 입력한다. 정상 사례와 질문 누락·근거 없는
동행 인물이 포함된 사례다. 프롬프트·입력·해시·개별 결과·항목 점수·범위·표준편차·N/A 건수는
`data/validation/<실행 시각>/`에 기록한다.

모델 설정이 같아도 의미 판정은 달라질 수 있다. 이 검증은 실제 사용자 자료와 전문가 정답을 사용한
타당성 검증을 대체하지 않는다. 개선 예시를 검토하고 별도 사용자 자료로 항목별 판정 일치율을 확인해야 한다.

현재 `.agents`는 실행 환경에서 읽기 전용이므로 변경된 계약은 이 문서에 기록한다.
이 문서가 이전 stage-evaluation 문서의 '항목 점수를 LLM이 정함'에 대한 최신 보충 계약이다.
