# 채점 재현성 개선 보고

## 적용 내용

기존 v5 메트릭의 8개 단계·64개 항목·배점·확인 기준 원문을 유지했다. 해당 원문 뒤에
`criteria-ratio-v1` 환산 규칙과 단계별 합성 채점 예시를 추가했다. 이 정책 이름은 원본 메트릭
버전과 별개이며 실제 프롬프트 버전은 다음 운영 채점 때 기존 레지스트리에 자동 기록된다.

변경 전에는 AI가 각 항목에서 몇 점을 줄지 정했다. 변경 후에는 총 194개 세부 기준에 대해
평가 건수·통과 건수·실패 위치·이유를 반환하고, 코드가 항목별 적용 기준의 통과율 평균에
배점을 곱해 정수로 반올림한다. 같은 판정 건수에서 임의로 1~5점을 가감할 수 없다.

| 변경 | 적용 범위 |
| --- | --- |
| 만점·부분점수·0점·N/A 환산 예시 | 모든 항목, 현재 배점에 맞춰 생성 |
| 의미 판정의 경계 예시 | 8개 단계별 별도 문서 |
| 중복 감점 제한 | 동일 기준·동일 단위는 한 번, 다른 명시적 기준 위반은 각각 반영 |
| 결정론 검사 | 기본 Question의 생성 수·ID 대응 및 40자 길이 |
| 입력과 출력 누락 구분 | 질문 입력이 있는데 출력이 전부 비어도 채점 가능하게 수정 |
| 원문 파싱 보완 | 한 줄 JSON 배열의 섹션 오인 방지, JSON 뒤 안내 문장 처리 |
| 결과 호환 | 기존 항목 점수·총점 구조 유지, checks와 scoringPolicy 추가 |
| 화면 | 실제 채점 프롬프트, 확정 코드 판정, 세부 판정 건수 조회 |

항목 점수는 `배점 × 평균(passed/total)`이다. total=0인 조건만 제외한다.
예를 들어 20점 항목의 두 기준이 각각 4/5, 5/5 통과면 18점이다. 4/5, 0/0이면 16점이다.
모든 기준이 0/0이면 N/A, 입력 5개가 있고 모두 실패했다면 0점이다.

사용자가 화면에서 편집한 기준에도 계산 규칙과 현재 배점의 환산 예시는 적용한다.
편집본에 원본 전용 의미 예시와 결정론 검사를 강제로 적용하지 않는다.

## 검증

- 전체 unittest 174개 통과.
- 8개 단계의 모든 원문 포함, 기준 ID 누락·추가 거부 및 strict JSON Schema 확인.
- 만점·부분점수·0점·N/A·.5 반올림·잘못된 건수·실패 근거 누락 검증.
- 질문 누락·중복·알 수 없는 ID·빈 문자열·40/41자 경계 검증.
- 새 결과의 기존 저장/조회 형태 호환, 편집본 기준 교체 검증.
- Streamlit 테스트 실행에서 예시 원문·세부 판정 확장 영역 렌더링 오류 없음.
- 저장된 실제 trace의 Question 입력을 읽어 coverage·expression 코드 검사가 활성화됨을 확인.
  실제 사용자 데이터를 새로 채점하거나 기존 운영 평가 결과를 덮어쓰지는 않았다.

## 반복 채점 실험

현재 앱의 CLI 기본 모델과 같은 `gpt-5.6-sol`을 명시해 고정했다. 정상 합성 사례와
질문 1개 누락·근거 없는 동행 인물이 포함된 합성 사례를 각각 기존 Question v2와 개선
방식으로 5회씩, 총 20회 채점한다. 두 사례는 프롬프트 예시 원문과 다른 보류 사례다.
전체 점수의 전문가 확정 정답은 없으며 질문 생성 항목의 기대 점수는 각각 20점·15점이다.

실험 완료: 총 20회 성공, 유효 실험의 호출·스키마 오류 0회. 모든 실행에서 항목 N/A는 0개였다.

| 합성 사례 | 방식 | 5회 점수 | 최대−최소 | 표준편차 |
| --- | --- | --- | --- | --- |
| 정상으로 구성한 사례 | 기존 | 100, 100, 100, 100, 100 | 0 | 0.00 |
| 정상으로 구성한 사례 | 개선 | 99, 100, 100, 100, 100 | 1 | 0.40 |
| 누락·근거 없는 동행 포함 | 기존 | 91, 91, 76, 92, 89 | 16 | 5.98 |
| 누락·근거 없는 동행 포함 | 개선 | 74, 74, 74, 74, 74 | 0 | 0.00 |

결함 사례의 질문 생성 항목은 기존 14, 15, 0, 15, 14점으로 흔들렸고, 개선 방식은 모두
`20 × 3/4 = 15점`으로 일치했다. 동행 인물의 근거 부족 경고는 양쪽 모두 5회 전부 발견했다.
이 사례에서는 오류를 발견하는 것보다 점수로 환산하는 방식에서 차이가 컸다.

정상 사례에서 1회 발생한 1점 차이는 event_grounding c02에 국한됐다. '무엇을 새롭게
배웠나요?'를 생각·감정·이유·인상 중 하나를 묻는 질문으로 인정하지 않은 실행이었다.
다른 항목 점수는 5회 모두 일치했다. 따라서 모든 상황의 편차가 감소했다고 결론 내리지 않는다.

## 해석과 한계

숫자 환산은 결정론적으로 바뀌었지만 의미 판정까지 결정론적이 되는 것은 아니다.
정상 사례의 '배운 점' 질문을 생각·인상 질문으로 인정하는지에서 1점 차이가 관측됐다.
기존 기준 사이의 해석 경계를 사람이 확정하고 예시를 추가할 필요가 있다.

새 방식은 적용 기준에 동일 가중치를 부여하므로 이전 방식과 절대 점수가 달라질 수 있다.
기존 점수와 새 점수를 직접 비교해 생성 품질이 좋아지거나 나빠졌다고 판단해서는 안 된다.
같은 데이터 묶음을 새 기준으로 다시 채점해 기준선을 정해야 한다.

8개 단계 전부에 실제 모델 반복 실험을 한 것은 아니다. 현재 실험은 Question의 합성 사례
2개에 한정된다. 실제 사용자 자료의 항목별 전문가 판정과 비교해야 정확성·일반화 효과를
평가할 수 있다. 예시는 AI가 작성한 합성 초안이며 전문가가 승인한 정답 데이터는 아니다.
이번 비교는 예시·고정 환산식·결정론 검사를 함께 적용한 효과다. 예시 추가만의 효과를
분리해 측정한 실험은 아니다. 모델의 추론 설정은 당시 CLI 설정(xhigh)을 공통으로 사용했다.

기존 시간 항목의 미완성 Calendar/window 조건과 User Memory의 500자/별도 측정 설명
200자 차이는 원문을 임의로 고치지 않고 적용 규칙·예시에서 명시했다. 미완성 조건은
'기준 모호' 사유로 미평가하며, 길이는 실제 LLM 확인 기준의 500자를 따른다.

세부 기준별 근거가 늘어나므로 요청·응답 길이가 증가한다. 반복 실험으로 드러난 모호한
판정을 보강하고 실제 자료에서 타당성을 확인하는 것이 다음 검증 과제다.
