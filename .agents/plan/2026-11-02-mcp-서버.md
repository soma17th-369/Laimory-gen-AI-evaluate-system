# 로컬 MCP 서버

- 상태: 진행
- 관련 이슈: #12

## 배경·목표

수집과 채점을 지금은 Streamlit 화면에서 사람이 버튼으로만 실행한다. 대상 AI의 프롬프트는 이 저장소 밖에
있어서, 프롬프트를 고치는 에이전트가 결과를 확인하려면 사람이 화면을 오가야 한다.

로컬 MCP 서버를 붙여 에이전트가 **수집 → 선택 → 채점**을 직접 호출하게 한다. 끝났을 때 에이전트가 이
흐름을 끝까지 실행하고, 결과가 `채점 결과` 화면에도 그대로 보여야 한다.

## 범위 / 범위 밖

- 포함: 도구 5개(`sync_logs`, `list_logs`, `get_log`, `judge_task`, `get_job`), stdio 연결, 선행 저장 개선
- 범위 밖: 채점 기준 수정, 점수 직접 기록, 개선책·테스트 데이터 생성, dev 테스트 호출, HTTP·원격 접속

## 접근

### 선행 작업 (PR 1)

화면과 MCP 서버는 **별도 프로세스**다. 지금 저장 방식은 프로세스 하나를 전제로 해서 그대로 붙이면 기록이
유실될 수 있다.

- **서비스 계층:** 채점 대상 판별과 채점·저장 흐름을 `app/tasks/review.py` 로 옮긴다. 화면은 진행 표시만
  덧붙인다. MCP 서버가 `streamlit` 을 불러오지 않게 하는 것이 조건이다.
- **원자적 쓰기:** 임시 파일에 쓴 뒤 `os.replace` 로 바꾼다. 읽는 쪽은 항상 완전한 파일을 본다.
- **깨진 파일 보호:** 지금은 깨진 파일을 빈 값으로 읽고 그 위에 덮어쓴다. 읽고-합쳐-쓰는 경로는 깨진 파일이면
  멈춘다.
- **프로세스 간 잠금:** `filelock` 을 쓴다. 프로세스가 죽으면 OS 가 풀어 주므로 직접 만든 잠금 파일처럼
  남아서 막는 일이 없다. 대상은 수집 저장, 채점 레코드, 프롬프트 레지스트리다.
- **수집은 저장 직전에 다시 합친다.** 수집 전체를 잠그면 호출 한도 대기 동안 다른 프로세스가 멈춘다. 잠금은
  저장 순간에만 잡고, 디스크의 행을 다시 읽어 합친다.
- **단계별 저장:** 단계가 끝날 때마다 저장한다. `on_done` 을 끝난 순서로 부르고, 한 번의 채점은 같은
  `runId` 로 묶는다.
- **상세 조회:** `get_trace` 에 호출 한도 대기를 넣고, 로컬 `trace.json` 을 먼저 쓴다. 없는 로그는
  `TraceNotFound` 로 구분한다.

### MCP 서버 (PR 2)

- `mcp` 2.x 의 `MCPServer` 를 쓴다(1.x 의 `FastMCP` 는 이름이 바뀌었다).
- `app/mcp_server.py` 는 얇은 연결 층이다. 로직은 서비스 계층에 둔다.
- 오래 걸리는 작업은 프로세스 안의 작업 표로 관리한다. 서버 프로세스가 끝나면 작업 표는 사라지지만, 끝난
  단계의 결과는 저장소에 남는다.
- 도구 계약은 [MCP 명세](../../docs/MCP-명세.md) 를 따르고, 구현하며 바뀐 점은 같은 PR 에서 맞춘다.
