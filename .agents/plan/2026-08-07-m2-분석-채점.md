# M2 — 분석·점수·문제점 (설계 확정 → 구현)

- 상태: 완료 · 라이브 채점 검증 통과 (judge 모델 gpt-5.6-sol)
- 선행: M0·M1 완료(트레이스 목록·상세 조회)
- 관련: [로드맵](2026-08-07-mvp-roadmap.md), [시스템 개요](../knowledge/domain/overview.md)

> 이 문서는 **구현 착수 전 합의용 초안**이다. 아래 rubric·척도·모델은 제안이며, 확정되면
> 코드(openai 의존성·judge·GUI)를 붙인다. 실제 트레이스 구조로 검증하며 조정한다.

## 목표

선택한 트레이스(대상 AI 의 한 실행)를 **LLM judge(OpenAI)** 로 채점하고 문제점을 뽑아,
GUI 에 점수표와 문제점 목록을 보여준다. 이 결과가 이후 M3 리포트·M4(프롬프트 개선·테스트
데이터)의 근거가 된다.

## 1) 평가 단위 — 무엇을 채점하나 (제안)

- **트레이스 1건 = 채점 1건.** 대상 서버의 `main-agent` 한 실행이 곧 "하루 타임라인 생성"
  이므로, 그 최종 산출물의 품질을 평가한다.
- **근거(evidence)**: trace input(수집 스냅샷) + 최종 타임라인 출력 + (선택) 관측치 요약.
  - ⚠️ 확인 필요: "최종 타임라인"이 `trace.output` 에 있는지, 아니면 특정 관측치
    (`confirm-timeline-draft` / `main-agent` output)에 있는지 실제 트레이스로 확정한다.
- 지금은 **on-demand 단건 채점**(선택 트레이스에 버튼). 대량 일괄 채점은 M3 이후.

## 2) Rubric — 채점 기준 (제안, 대상 도메인 계약 기반)

| # | 기준 | 본다 |
| --- | --- | --- |
| 1 | 근거 충실성/환각 | 출력이 입력 수집 원본에 근거하는가. 지어낸 사건·장소·시간 없음 |
| 2 | 시간 정합성 | event 시각·순서가 window·수면 경계·근거 구간과 모순 없는가 |
| 3 | 장소 정합성 | 장소/주소가 근거에 있고 잘못 붙지 않았는가 |
| 4 | 완결성 | 주요 활동·캘린더 일정 누락 없이 하루가 설명되는가 |
| 5 | 문장 품질(노출) | title·description 이 1인칭 해요체 과거형, 추정표현·분단위 시각·원시 수치 배제, 길이 적정 |
| 6 | 회고 질문 | 모든 event 에 해요체 의문문·40자 내외 질문이 붙었는가 |
| 7 | 전반 | 하루 기록으로 읽었을 때의 종합 품질 |

> 기준은 가감 가능. 지금 가장 보고 싶은 축을 알려주시면 반영한다.

## 3) 척도·출력 계약 (제안)

- 각 기준 **0~10 정수**(0=심각 위반 … 10=문제 없음) + 기준별 근거 한 줄.
- **overall 0~10**(단순 평균이 아니라 judge 의 종합 판단).
- **findings[]**: `{criterion, severity(HIGH|MED|LOW), 설명}` — 문제점 목록.
- OpenAI **structured output(JSON schema)** 로 강제해 파싱 안정화. 스키마는 Pydantic 으로 선언.

## 4) 모델·설정 (제안)

- provider: **OpenAI**. 의존성 `openai` 추가(`uv add openai`).
- env 추가: `OPENAI_API_KEY`(SecretStr, 없으면 채점 비활성), `OPENAI_JUDGE_MODEL`
  (기본 `gpt-4o` — 더 정확한(비싼) 모델. `.env` 에서 언제든 교체 가능).
- 키는 M1 과 동일하게 `SecretStr`, 값 미로깅.

## 5) judge 프롬프트 원칙

- judge 에는 **근거(입력 스냅샷·최종 출력)** 를 주고, "근거에 없는 건 감점" 을 규칙으로 못박는다.
- 점수는 **근거 인용과 함께** 요구(왜 그 점수인지). 화면 리포트에는 값 인용 허용(로컬 분석 도구),
  단 **운영 로그·관측에는 본문·점수 근거를 남기지 않는다**(M1 정책 유지).
- 프롬프트는 `app/analysis/` 아래 파일로 두고 버전 관리.

## 6) GUI 통합 (제안)

- 상세 화면에 **"이 트레이스 채점"** 버튼 → judge 호출 → 점수표(기준별 0~5 + overall) +
  문제점 목록 표시. 결과는 session_state 에 캐시.

## 리스크·미결 (확인 필요)

- ✅ rubric·척도 확정: 7기준 그대로, 척도 **0~10**.
- ✅ judge 모델 확정: 기본 **gpt-4o**, `OPENAI_JUDGE_MODEL` 로 교체 가능.
- ✅ **최종 출력 위치** 확정: `main-agent` 관측치 `output.timeline.events`. `trace.output` 은
  운영 메타(status·persisted·tokenUsage)뿐이라 채점 근거로 부적합 → 교정 완료.
- ⬜ **비용**: 트레이스가 1만+건. 단건 on-demand 로 시작해 비용 통제.
- ⬜ **트레이스 종류별 편차**: timeline 관측치가 없는 트레이스는 `trace.output` 폴백(불완전
  근거로 표시). rubric 은 timeline-generation 트레이스를 전제한다.
