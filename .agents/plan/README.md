# Plan

규모 있는 작업은 **구현 전에** 여기에 계획을 남깁니다. 무엇을 어떻게 나눠서 할지 미리
정리해 두면 커밋 단위와 검증 범위가 분명해집니다.

## 언제 쓰나

- 여러 파일·여러 커밋에 걸치는 기능/리팩터링.
- 계약·동작이 바뀌어 검토 포인트를 미리 정리해야 하는 작업.
- 사소한 한 줄 수정에는 만들지 않습니다.

## 파일 규칙

- 파일명: `YYYY-MM-DD-<kebab-제목>.md` (이슈가 있으면 `<이슈번호>-<제목>.md` 도 가능).
- 문서 맨 위에 상태를 적습니다: `상태: 제안 | 진행 | 완료 | 보류`.
- 완료된 계획은 지우지 말고 상태만 `완료` 로 바꿔 남깁니다(이력).

## 문서 골격

```markdown
# <제목>

- 상태: 제안
- 관련 이슈:

## 배경·목표
왜 하는지, 끝났을 때 무엇이 참이어야 하는지.

## 범위 / 범위 밖
포함하는 것과 이번에 하지 않는 것.

## 접근
어떻게 풀지. 대안이 있었다면 왜 이 방법인지.

## 작업 분할
- [ ] 커밋 단위 1 — ...
- [ ] 커밋 단위 2 — ...

## 검증
어떤 테스트·수동 확인으로 완료를 판단하는지.

## 리스크·미결
```
