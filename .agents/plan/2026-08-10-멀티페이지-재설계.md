# 멀티페이지 재설계 (대시보드 + 파일 저장)

- 상태: 진행 (4페이지 + 파일저장 완성 · Page2 trace.json 구현 완료)
- 선행: M0~M4 (main 머지 완료). 기존 서비스 모듈 재사용.

## 목표

단일 페이지 흐름을 **4개 페이지 + 파일 저장(data/)** 로 재구성한다. 로직(langfuse_client·
analysis·report·improve·testdata)은 재사용하고 UI·저장 계층을 새로 얹는다.

## 페이지

1. **대시보드** — 수집된 로그 통계·총 사용량(트레이스 수·토큰·비용·이름별 분포 등). data/ 를 집계.
2. **Task 리뷰·채점** — task id 별로 로그 모아 전체 처리과정 확인 + LLM judge. 프롬프트 모아 따로
   확인. 결과 파일 저장. ⛔ **저장 파일 구조는 사용자 "안내용 파일"에 맞춘다(중복 금지).**
3. **개선책** — task id 별 평가를 골라 모아 하나의 개선책 생성(여러 task 문제점 통합). 평가기준·
   지령은 화면에서 편집 후 전송. 결과 파일 저장.
4. **테스트 데이터** — (a) 개선책 기반 검증용, (b) 수집 input 기반 실행용. 두 기능.

## 데이터 레이아웃 (data/, gitignore)

```
data/
├── tasks/<taskId>/{trace.json, prompts.json}   # ② ⛔구조 안내파일 대기
├── evaluations/<taskId>.json                    # ② judge 결과(task별)
├── improvements/<slug>.json                     # ③ 개선책(여러 task 통합)
└── testdata/{from-improvement,from-logs}/<slug>.json  # ④
```

## 기술

- Streamlit **`st.navigation` + `st.Page`** 단일 진입점(`app/main.py`). 페이지는 `app/ui/*.py` 의 `render()`.
- 저장 계층 `app/storage/`: `paths.py`(경로 규칙=정본), `store.py`(save/load/list json, ensure_ascii=False).
- 설정 `app/config.py` 에 `data_dir` 추가.
