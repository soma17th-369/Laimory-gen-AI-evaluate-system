# LangFuse 개발·운영 저장소를 한 목록으로 함께 관리

- 상태: 완료
- 관련 이슈:

## 배경·목표

LangFuse 저장소가 개발용·운영용 **두 개**로 나뉘었다. 지금 코드는 `.env` 의 키 한 벌
(`LANGFUSE_PUBLIC_KEY` / `LANGFUSE_SECRET_KEY` / `LANGFUSE_HOST`)로 클라이언트를 하나만 만들고,
수집 결과도 한 곳에만 쌓는다. 운영 프로젝트를 보려면 `.env` 를 바꿔치기해야 하고, 그러면 이미
쌓인 개발 로그 위에 운영 로그가 섞이며 커서(`collection.state.json`)도 서로를 밀어낸다.

목표: **두 프로젝트를 한 목록에 합쳐 시간순으로 본다.** 화면을 환경으로 가르지 않고, 각 행이
개발에서 왔는지 운영에서 왔는지만 알 수 있으면 된다.

## 결정 사항

1. **합쳐 담는다.** 저장 파일은 하나(`data/collection.json`)이고, 행마다 `env` 가 붙는다.
   정렬은 환경과 무관하게 `timestamp` 내림차순. 폴더를 환경으로 쪼개지 않는다 — 트레이스 id 와
   taskId 가 전역 유일(32자리 hex · UUIDv7)이라 파일명이 부딪히지 않는다.
2. **환경이 갈리는 자리는 셋뿐**이다: 자격증명, 조회 클라이언트, 동기화 커서. 커서는
   `collection.state.json` 안에서 환경을 키로 나눠 담는다("어디까지 훑었는지"는 프로젝트마다
   다르고, 합치면 서로를 밀어내 양쪽 다 구멍이 난다).
3. **환경은 명시적으로 넘긴다.** 조회 함수(`get_client`·`get_trace`·`list_traces`·
   `list_generations`)와 `sync()` 는 `env` 를 기본값 없이 받는다. 빠뜨렸을 때 조용히 한쪽만
   조회하는 것보다 바로 드러나는 편이 낫다. 상세 조회는 **그 행의 `env`** 를 따라간다.
4. **키 이름은 환경 접두사.** `LANGFUSE_DEV_*` / `LANGFUSE_PROD_*`. 접두사 없는 예전 이름은
   **dev 값**으로만 읽어 쓰던 `.env` 가 그대로 동작하게 한다. prod 에는 이 fallback 을 두지
   않는다(운영 키를 안 넣었는데 다른 프로젝트를 운영이라고 믿고 보는 사고를 막는다). `host` 는
   두 프로젝트가 같은 인스턴스인 경우가 흔하므로 공통 `LANGFUSE_HOST` 로 떨어뜨린다.
5. **수집은 키가 갖춰진 환경 전부**를 한 번에 훑는다. 버튼을 환경별로 나누지 않는다.
6. **환경 선택 UI 를 두지 않는다.** 화면을 가르지 않기로 했으므로 고를 것이 없다. 건수만 환경별로
   함께 보여준다.

## 범위 / 범위 밖

- 포함: 환경 키 모듈, 환경별 자격증명 해석, 환경별 클라이언트, 환경별 커서, 행·레코드의 `env`
  표시, 전 페이지 환경 표기, 단위 테스트, 계약 문서·README·`.env.example`.
- 범위 밖: 환경별 필터 UI, dev/prod 를 나란히 놓는 교차 비교, 3번째 환경(staging 등),
  개선책 반영 시기를 환경마다 따로 두는 것.

## 작업 분할

1. `app/environments.py` — 환경 키·라벨·`of()`(레코드가 어느 환경에서 왔는지).
2. `app/config.py` — 환경별 자격증명 해석(`LangfuseCredentials`·`configured_environments`).
3. `app/langfuse_client.py` — 환경별 클라이언트 + 조회 함수 `env` 필수.
4. `app/collect/sync.py` — 행에 `env`, 커서를 환경별 map 으로, `sync(env)` · `sync_all(envs)`.
5. `app/collect/generations.py` — `(traceId, env)` 쌍으로 조회.
6. `app/ui/log_collection.py` — 설정된 환경 전부 수집 + 환경별 현황 표.
7. `app/ui/dashboard.py` · `task_review.py` · `evaluation_results.py` · `improvement_history.py` ·
   `testdata.py` · `app/improve/compare.py` — 환경 표기와 행별 환경 추적.
8. `tests/test_environments.py` 추가, `test_collection_sync.py` 에 합침·커서 독립 테스트 추가.
9. 문서: `domain/langfuse-environments.md`(신규) · `collection-store.md` · Router · README ·
   `.env.example`.

## 검증

- `tests.test_environments` — 레코드의 환경 판정, 키 해석(접두사·레거시·host fallback), 키 없는
  환경의 클라이언트 거부.
- `tests.test_collection_sync` — 두 환경이 한 목록에 시간순으로 들어가는지, 커서가 환경마다
  독립인지, 한 환경 재수집이 다른 환경 행을 지우지 않는지, 예전 평면 커서·`env` 없는 행이
  `dev` 로 읽히는지.
- 실제 앱 구동: 전 페이지 예외 없이 렌더링, 개발 로그 13,018건이 그대로 보이고 운영은 0건 표시.
