# PR 관례

## 우선순위

- 저장소에 `.github/pull_request_template.md` 가 있으면 **그 템플릿이 우선**입니다.
  이 문서는 템플릿이 없거나 보완이 필요할 때의 기준입니다.
- PR 생성·병합은 사용자가 요청하거나 승인한 경우에만 합니다.

## PR 본문에 담을 것

- **무엇을 왜** 바꿨는지 (배경·목적). 연결된 이슈가 있으면 링크합니다.
- **바뀐 계약·동작** 요약. 겉으로 드러나는 변화(입력/출력/설정/실행 방법)를 먼저 적습니다.
- **검증 방법**: 어떤 테스트·수동 확인을 했는지, 재현 방법.
- **범위 밖(non-goal)** 이나 후속 작업이 있으면 명시합니다.

## 커밋 구성

- [커밋 관례](commit.md) 에 따라 독립적으로 검토·되돌릴 수 있는 단위로 나눕니다.
- 리뷰어가 커밋을 순서대로 따라가며 이해할 수 있게 구성합니다.

## 검토할 때

- 변경이 이슈/PR 목적 범위 안에 있는지, unrelated 변경이 섞이지 않았는지 봅니다.
- 계약·동작이 바뀐 곳이 있으면 관련 knowledge 문서가 같은 PR 에서 갱신됐는지 확인합니다
  (파일만 바뀐 게 아니라 **의미**가 바뀐 경우).
- 실제 secret·token·사용자 원문이 코드·문서·로그에 들어가지 않았는지 확인합니다.
