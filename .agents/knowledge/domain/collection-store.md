# 수집 저장소 (collection.json)

## Scope

LangFuse 트레이스를 로컬에 **누적 저장**하는 규칙과 증분 동기화 계약. 대시보드·Task 리뷰·
테스트 데이터 페이지가 공유하는 단일 원천이다. 여러 LangFuse 프로젝트(dev·prod)를 한 목록에
합쳐 담는다(→ [LangFuse 환경](langfuse-environments.md)).

## 정본 파일

| 파일 | 내용 | 불변식 |
| --- | --- | --- |
| `data/collection.json` | 지금까지 수집한 트레이스 요약 배열 | `id` 유일 · `timestamp` 내림차순(최신 먼저) · 한 번 들어온 행은 재수집으로 지워지지 않는다 |
| `data/collection.state.json` | **환경별** 동기화 커서 (`{"dev": {…}, "prod": {…}}`) | 각 값은 `backfilled` · `last_timestamp`(연속 훑기의 끝) · `last_synced_at` · `total`(그 환경의 저장 행 수) |

행 스키마(고정): `id` · `env` · `taskId` · `name` · `timestamp` · `user_id` · `latency` ·
`total_cost`. 트레이스 하나는 v2 관측치를 `traceId` 로 묶어 만든다(→ `app/langfuse_client.py`).
`name`·`timestamp`·`latency`·`user_id` 는 루트 관측치의 `traceName`(없으면 이름)·시작 시각·latency·
userId, `total_cost` 는 그 트레이스 관측치의 `totalCost` 합이다. `taskId` 는 루트의 세션 id 다(대상
서버가 taskId 를 세션으로 남긴다). 세션이 없는 트레이스(대상 서버 테스트 조각)는 `taskId` 가 비고,
예전 목록이 입력에서 꺼내 저장해 둔 값은 병합할 때 지킨다.
`env` 는 이 행이 어느 LangFuse 프로젝트에서 왔는지이며, 화면이 개발/운영을 구분하는 **유일한**
근거다. `env` 가 없는 행은 환경 구분이 생기기 전 데이터라 `dev` 로 읽는다.

## 동기화 계약

- **합쳐 담기**: 저장 파일은 하나다. 환경으로 폴더를 나누지 않고 행의 `env` 로 구분하며,
  정렬은 환경과 무관하게 `timestamp` 내림차순이다. 트레이스 id 가 전역 유일이라 `id` 병합이
  그대로 성립한다.
- **커서는 환경마다**: `sync(env)` 는 한 환경만 훑고 그 환경의 커서만 옮긴다. 다른 환경의 행도
  커서도 건드리지 않는다. 커서를 하나로 합치면 두 프로젝트가 서로를 밀어내 양쪽 다 구멍이 난다.
  환경 구분이 없던 시절의 평면 커서(`{"backfilled": …}`)는 `dev` 것으로 읽는다.
- **누적**: 수집은 교체가 아니라 `id` 기준 병합이다. 같은 `id` 는 새로 받은 값으로 갱신하고,
  LangFuse 가 더 이상 돌려주지 않는 행도 저장소에는 남는다. 단 **처음 시각과 `taskId` 는 저장본을
  지킨다.** 대상 서버 테스트가 옛 트레이스 id 를 재사용하면 구간마다 새 루트가 보여 시각이 뒤로
  밀리고, 세션 없는 루트는 `taskId` 를 주지 않기 때문이다.
- **보존**: LangFuse 는 오래된 트레이스를 지운다(2026-11 확인 기준 v2 로는 약 30일치만 나온다).
  행을 지우지 않으므로 이 파일이 유일한 과거 목록이고, 채점한 Task 의 `trace.json` 이 유일한 본문이다.
- **커서**: `last_timestamp` 는 **연속으로 훑은 구간의 끝**이다. 이번 조회에서 실제로 받은 행의
  최신 시각으로만 전진하며, 저장된 행 전체의 최대 시각이 아니다(최신 구간만 담긴 옛 스냅샷이
  남아 있을 때 커서가 튀어 중간 구간을 건너뛰는 것을 막는다). 다음 동기화는 이 시각보다
  `LOOKBACK`(1시간) 앞에서 시작한다. 루트 관측치는 트레이스가 끝나야 올라오므로, 커서보다 먼저
  시작했지만 늦게 끝난 트레이스를 놓치지 않으려는 것이다. 겹친 행은 `id` 병합이 흡수하고, 앞당겨 받은
  구간의 행만 받았을 때도 커서는 뒤로 물러나지 않는다.
- **전체 수집(backfill)** 조건: 커서가 없거나 사용자가 명시적으로 요청했을 때. `HISTORY_START`
  (2026-07-01)부터 트레이스가 처음 나오는 구간을 이분 탐색으로 찾아 거기서부터 훑는다.
- **필터 없음**: 수집 대상은 항상 프로젝트 전체 트레이스다. name·user_id 같은 조회 필터를 두면
  커서가 어떤 범위를 훑은 것인지 달라지므로 도입하지 않는다.
- **필드**: 구간마다 루트 관측치(`isRootObservation`, `fields="core,basic,metrics,trace_context"`)
  와 비용이 0 보다 큰 관측치(`fields="core,usage"`)만 받는다. 루트 입력은 원본 데이터 전체라 받지
  않는다. 비용은 구간 끝보다 `COST_SLACK`(1시간) 더 받아 구간 끝 직전에 시작한 트레이스의 자식도 합친다.
- **구간 순서**: v2 관측치 API 는 결과를 시작 시각 **내림차순**으로만 주고 정렬을 바꿀 수 없다.
  그래서 하루 단위 구간(`WINDOW`)을 오래된 쪽부터 차례로 부르고, 구간 하나는 통째로 받은 뒤에
  반영한다. 그래야 중간에 끊겨도 `last_timestamp` 가 안전한 워터마크가 되어 다음 실행이 이어받는다.
  결과의 `pages` 는 훑은 구간 수다(예전 페이지 수 자리라 이름을 유지).
- **중단 시 저장**: 조회가 예외로 끊겨도(호출 한도·네트워크·화면 중단) 그때까지 받은 행과
  커서를 저장한 뒤 예외를 올린다. 한 구간도 못 받았으면 아무것도 쓰지 않는다.
- **호출 한도**: 트레이스 목록·상세 API(`/api/public/traces`)는 2026-11-16 에 없어졌다(410
  `LANGFUSE_V3_API_REMOVED`). 조회는 전부 v2 관측치 API 로 하며 한도는 분당 30회다(2026-10 확인).
  429 는 `retry-after` 만큼 기다렸다가 다시 부르고(`app/langfuse_client.py`), 그래도 계속 막히면
  오류를 올린다.
- **동시 저장**: 수집 전체를 잠그면 호출 한도를 기다리는 동안 다른 프로세스까지 멈춘다. 그래서 저장
  순간에만 `store.locked` 를 잡고, 디스크의 행과 커서를 다시 읽어 이번에 받은 행을 합친다. 다른
  프로세스가 그 사이 저장한 행과 다른 환경의 커서가 밀려나지 않는다.
- **깨진 저장소**: `collection.json` 을 읽을 수 없으면 수집을 시작하지 않고 `CorruptJson` 으로 멈춘다.
  빈 목록으로 읽으면 쌓인 로그를 이번에 받은 행으로 덮어쓰기 때문이다.
