## 결정과 근거

- **OpenAI structured output** 은 `client.chat.completions.parse(response_format=<Pydantic>)`
  (openai 2.53.0 에서 stable, beta 아님). 키 없이 `type_to_response_format_param` 로 strict 스키마
  변환이 되는지 사전 검증 → OK(전 필드 required, strict=True).
- **점수 범위(0~10)를 스키마 제약(minimum/maximum)으로 넣지 않음** — strict 모드 호환성 위해.
  프롬프트로 지시하고 코드에서 clamp.
- **temperature=0 실패 시 재시도**: o-series 등 일부 모델이 temperature 를 막아, 오류 메시지에
  'temperature' 가 있으면 빼고 재호출.
- **평가 단위 = 트레이스, 근거 = trace.input + trace.output + 관측치 이름**. 최종 출력 위치는
  우선 `trace.output` 로 두고 라이브에서 충분성 확인(관측치 본문은 크기·비용 때문에 이름만).
- **키 취급은 M1 과 동일**: SecretStr, 값 미로깅. 키 없으면 채점 버튼 비활성(조회는 정상).

## 근거 교정 (중요 — trace.output 은 타임라인이 아니었다)

- 실제 LangFuse 포맷을 뜯어보니 **`trace.output` 에는 최종 타임라인이 없다**. status·persisted·
  callbackSent·tokenUsage 같은 **운영 메타뿐**이다.
- 최종 산출물(events)은 **관측치 `main-agent` 의 `output.timeline.events`** 에 있다. 각 event 는
  clientEventId·eventType·title·description·address·placeLabel·startTime·endTime·confidence·
  inferenceLevel·sourceRefs·uncertainty·**question** 필드를 가진다 — rubric 7기준과 직접 대응.
- 즉 **초기 라이브 채점은 잘못된 근거(input+운영메타)로 나온 점수**였다. judge 가 실제 타임라인을
  못 보고 있었다. `assemble_evidence` 를 `find_final_timeline`(관측치 우선순위 main-agent→
  question-agent→store-timeline, 폴백 trace.output)으로 교정.
- 교정 후 재채점(gpt-5.6-sol)은 실제 event(title·시각)를 근거로 지적: 시간 4→3, 문장 6→5,
  findings 16→14. summary 가 구체 사건("동원마을 체류 배치", "20:44 이후 기록")을 인용.
- **교훈**: LLM judge 를 붙이기 전에 **입력·출력 raw 포맷을 반드시 실물로 확인한다.**
  (사용자 지적으로 발견 — 포맷 미확인 채 진행하면 안 된다.)
