# 2026-09-05 — 파이프라인 설명 페이지

## 배경

평가 대상인 Laimory-AI 서버가 Timeline 과 User Memory 를 어떤 순서로, 어느 단계를 LLM 에
맡기고 어느 단계를 코드가 확정하는지 적은 문서(단일 HTML, Laimory-AI 저장소에서 생성)가 있다.
로그를 읽으면서 "이 GENERATION 이 파이프라인의 어디인가" 를 매번 다른 저장소를 열어 확인하는
대신, 이 앱 안에서 바로 볼 수 있게 페이지로 넣었다.

## 한 것

- `assets/docs/laimory-pipeline.html` — 문서를 그대로 둔다(프롬프트 v2 세트 원문 11개 포함).
- `app/ui/pipeline_doc.py` 신규 — 문서를 `st.iframe` 으로 띄우는 페이지. 위에 **LangFuse 이름 ↔
  문서의 단계** 대응표(expander)를 둔다. 트레이스 `generate-timeline`/`update-user-memory` 와
  GENERATION 10종(`infer-*-events` · `describe-photo-images` · `generate-timeline-draft` ·
  `analyze-timeline-repair` · `generate-event-questions` · `update-user-memory-profile`)을
  문서의 Agent·노드에 잇는다. 이름은 이날 LangFuse(dev·prod)에서 실제로 확인한 것만 넣었다.
- `app/main.py` — 사이드바 대시보드 바로 아래에 "📖 파이프라인 설명"(`/pipeline`) 등록.
- `tests/test_pipeline_doc_ui.py` — 테마 전달·iframe 표시 규칙 삽입·저장된 문서 모양 10개.
- README 페이지 표·문서 위치. AGENT.md·overview.md 의 "프롬프트 원문 금지" 규칙 범위 조정(아래).

## 결정과 근거

- **문서를 다시 쓰지 않고 그대로 iframe 에 넣는다.** 2,700줄짜리 설계 문서를 Streamlit 위젯으로
  옮기면 유지가 두 배가 된다. 문서가 바뀌면 파일만 갈아 끼우면 되게 했다. iframe 이라 문서의
  CSS(`body`·`p`·`code` 전역 규칙)가 앱과 섞이지 않고, 문서의 목차·복사 버튼 스크립트도 그대로
  돈다. `st.markdown(unsafe_allow_html=True)` 는 전역 CSS 가 사이드바까지 덮어서 접었다.
- **프롬프트 원문을 저장소에 둔다(사용자 결정).** 처음에는 AGENT.md 의 "프롬프트 원문은
  저장소에 남기지 않는다" 를 따라 전체본은 `data/docs/`(gitignore)에, 저장소에는 원문 자리만
  비운 본을 두는 2단 구조로 만들었다. 사용자가 원문을 저장소에 남기겠다고 해서 단일 파일로
  되돌렸다. 그 규칙은 **LangFuse 에서 받은 로그 본문**(키·프롬프트·입출력)에 대한 것으로 범위를
  좁히고, 설명 문서는 예외로 적었다(AGENT.md·overview.md). 채점·개선책이 LangFuse 에서 받는
  프롬프트 원문은 여전히 `data/` 에만 남는다.
- **iframe 은 화면 높이만큼, 안에서 스크롤.** `st.iframe(height="content")` 로 통째로 펼치면
  문서의 왼쪽 목차(sticky rail)가 첫 화면과 함께 사라진다. 문서가 자기 창 안에서 스크롤돼야
  목차가 따라온다. 높이는 `[data-testid="stIFrame"]` 에 `calc(100vh - 230px)` 를 준다.
  `st.components.v1.html` 은 1.61 에서 deprecated 라 `st.iframe` 을 쓴다.
- **목차 링크는 스크립트로 잡는다.** srcdoc 문서의 기준 URL 은 앱 페이지라 `href="#t-confirm"`
  를 그대로 두면 iframe 이 `…/pipeline#t-confirm` 으로 이동해 **앱이 iframe 안에 다시 열린다**
  (실제로 그렇게 됐다). 렌더링 때 `</body>` 앞에 클릭 가로채기를 끼워 문서 자신의 스크롤만
  옮긴다. `scrollIntoView` 는 바깥 앱 화면까지 끌어올려 제목이 사라지므로 `scrollTo` 로 계산한다.
- **앱 안 표시 규칙은 렌더링 때만 끼운다.** 문서의 목차(rail)는 문서 폭 1080px 부터 펴지는데 앱
  본문 폭은 1500px 화면에서 1030px 이라 접힌다. 940px 부터 펴지는 규칙을 `</head>` 앞에 덧붙인다.
  저장된 문서 파일은 그대로라 갈아 끼우기가 쉽다.
- **테마는 `st.context.theme.type` → 문서의 `<html data-theme>`.** 문서가 이미 `data-theme`
  분기를 갖고 있어 값만 넘기면 된다. 못 읽으면 문서 기본(OS 설정)으로 둔다.
- **대응표는 이름으로만 잇는다.** 관측치 이름이 곧 Agent 이름이라 별도 근거가 필요 없다. 개발
  프로젝트의 Bedrock 테스트 실행에서 span 이 낱개 트레이스로 떨어진 이름(`main-agent` ·
  `call-llm` · `confirm-timeline-draft` 등)은 표에 넣지 않았다 — 정상 실행의 이름이 아니다.

## 막힌 점

- 브라우저 패널의 streamlit 서버(`.claude/launch.json`)는 `app/ui/*.py` 변경을 다시 읽지 않았다.
  코드가 반영 안 된 줄 알고 두 번 헛돌았다. UI 를 고친 뒤 확인할 때는 서버를 새로 띄운다.

## 열린 질문

- 문서는 프롬프트 **v2 세트**를 기준으로 쓰였고, 실행 중인 세트는 v1 이다(문서 자체가 그렇게
  밝힌다). 채점·개선책이 보는 프롬프트(LangFuse generation input)와 문서의 원문이 다를 수 있다.
