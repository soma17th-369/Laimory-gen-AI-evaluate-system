# 2026-11-02 MCP 선행 작업

## 한 일

이슈 #12 의 MCP 서버를 붙이기 전에 채점 흐름과 저장을 다른 프로세스에서도 안전하게 만들었다.

- 채점 대상 판별과 채점·저장 흐름을 `app/tasks/review.py` 로 옮겼다.
- `store.save_json` 을 원자적 쓰기로 바꾸고 `store.read_json`·`store.locked` 를 추가했다.
- 채점은 단계가 끝날 때마다 저장하고, 상세 조회는 로컬 저장본을 먼저 쓴다.

## 결정과 근거

- **잠금은 `filelock` 을 쓴다.** 프로세스가 죽으면 OS 가 풀어 준다. 직접 만든 잠금 파일은 남아서 다음
  실행을 막을 수 있다.
- **수집은 전체를 잠그지 않는다.** 호출 한도 대기가 길어서 전체를 잠그면 화면까지 멈춘다. 저장 순간에만
  잠그고 디스크를 다시 읽어 합친다. 같은 환경을 동시에 수집하면 커서가 뒤로 갈 수 있지만, 다음 수집이
  조금 더 받을 뿐 행은 빠지지 않는다.
- **`on_done` 을 끝난 순서로 바꿨다.** 예전에는 단계 순서로 회수해서 앞 단계가 오래 걸리면 끝난 뒤 단계의
  저장이 밀렸다. 화면 진행 표시의 순서만 달라진다.
- **`trace.json` 을 채점 전에 저장한다.** 점수가 하나라도 저장되면 그 근거가 있어야 한다. 모든 단계가
  실패해도 파일 하나가 남을 뿐이라 문제없다.
- **`domain_task_id` 를 없앴다.** 수집 행의 `taskId` 가 같은 규칙으로 만들어진 값이라 상세를 받기 전에도
  저장본을 찾을 수 있다. 행에 값이 없으면 상세의 값, 그다음 트레이스 id 를 쓴다.

## 확인한 것

- 잠금을 뺀 채로 `tests/test_concurrent_saves.py` 를 돌리면 프로세스 동시 저장과 레지스트리 번호 테스트가
  실패한다. 잠금을 넣으면 통과한다.
- LangFuse 의 없는 로그 오류는 `NotFoundError` 이고 `ApiError` 의 하위 형식이다(status 404).
- `Task 리뷰·채점` 화면에서 전체 채점을 눌러 가짜 채점기로 끝까지 돌렸다. 실패한 단계를 뺀 나머지가 같은
  `runId` 로 저장됐다.

## 막힌 점 / 열린 질문

- 화면에서 일부 단계가 실패해도 경고가 보이지 않는다. 채점 직후 `st.rerun()` 이 불려 `st.warning` 이
  지워진다. 이번 변경 전에도 같았고, 이번 범위 밖이라 두었다.
- `mcp` 패키지는 2.x 에서 `FastMCP` 가 `MCPServer` 로 바뀌었다. 예전 예제를 그대로 쓰면 불러오기가 실패한다.
