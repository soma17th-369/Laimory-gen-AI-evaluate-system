# 2026-08-20 — LangFuse 로그 누적 저장·증분 동기화

## 배경

기존 `app/ui/log_collection.py` 는 버튼을 누를 때마다 `list_traces(limit=N)` 로 **한 페이지만**
받아 `data/collection.json` 을 통째로 **교체**했다. 그래서

- 사용자가 지정한 개수만큼만 남고 그 이전 로그는 사라졌다(오래된 로그 조회 불가).
- 새 로그만 필요할 때도 매번 전체를 다시 받았다.

요구: **처음에는 쌓인 로그를 전부 받아 저장하고, 이후에는 저장된 것 이후에 생긴 것만 내려받기.**

## 결정

- 저장소를 "스냅샷 교체" → **"누적 병합"** 으로 바꿨다. `id` 기준으로 합치고, 서버가 더 이상
  돌려주지 않는 행도 지우지 않는다.
- 커서 파일 `data/collection.state.json` 을 추가했다(`backfilled`·`filters`·`last_timestamp`·
  `last_synced_at`·`total`). `collection.json` 자체의 스키마는 그대로 둬서 대시보드·Task 리뷰·
  테스트 데이터 페이지는 손대지 않았다.
- 조회 정렬을 **`timestamp.asc`** 로 고정했다. 처음엔 desc + `to_timestamp=now` 로 상한을 고정할까
  했지만,
  - asc 면 조회 중 새 로그가 들어와도 이미 본 페이지가 밀리지 않고,
  - 중간에 끊겨도 `last_timestamp` 가 안전한 워터마크라 다음 실행이 이어받으며,
  - 로컬 시계와 LangFuse 시계 차이에 의존하지 않는다(모든 시각이 서버가 준 값).

  그래서 전체 수집과 증분이 **같은 코드 경로**가 됐다. 차이는 `from_timestamp` 가 `None` 이냐
  커서냐 뿐이다.
- `from_timestamp` 는 경계 포함이라 마지막 트레이스를 매번 1건 다시 받는다. 누락 방지를 위해
  일부러 그대로 두고 `id` 병합으로 흡수한다.
- **조회 필터(name·user_id)를 아예 없앴다.** 처음엔 필터를 남기고 "필터가 바뀌면 전체 재수집"
  분기를 뒀는데, 사용자 확인 결과 이 페이지는 최신화만 하면 되는 화면이었다. 필터가 없으니
  커서가 항상 "전체 트레이스를 어디까지 훑었는지" 하나의 의미만 갖는다.
- **커서는 저장된 행의 최대 시각이 아니라 이번 훑기의 워터마크**로 잡았다. 처음엔 max(저장 행)
  으로 썼는데, 지금처럼 예전 스냅샷(최신 100건)이 남아 있는 상태에서 백필이 중간에 끊기면
  커서가 그 최신 시각으로 튀어 아직 못 받은 중간 구간을 영영 건너뛴다. 회귀 테스트로 고정했다.
- 목록 조회에 `fields="core,io,metrics"` 를 지정했다. 기본값은 관측치까지 실어와 100건 페이지
  하나가 수 초씩 걸렸다(실측: 전체 수집이 42페이지에서 수 분). 필요한 필드만 받으니 20건
  페이지가 0.4s 수준으로 떨어졌다.

## 변경

- 추가 `app/collect/sync.py` — 수집·병합·커서 저장의 정본. UI 는 여기만 호출한다.
- 추가 `app/storage/paths.py::collection_state_file()`.
- 수정 `app/langfuse_client.py::list_traces` — `order_by` 인자.
- 재작성 `app/ui/log_collection.py` — 입력 위젯 전부 제거. 진행률(`st.status`)과
  `새 로그 동기화` / `처음부터 다시 훑기` 두 버튼, 저장 현황 4개만 남겼다.
  `page_size`·`max_pages` 는 `sync()` 인자로만 남겨 테스트에서 쓴다.
- 추가 `tests/test_collection_sync.py` — 가짜 LangFuse 페이저로 전체 수집·증분·행 보존·
  필터 변경·중단 후 이어받기 검증.
- 추가 `.agents/knowledge/domain/collection-store.md` + Router 한 줄.
