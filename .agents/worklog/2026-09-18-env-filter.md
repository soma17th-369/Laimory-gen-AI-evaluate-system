# 2026-09-18 로그 화면 공통 환경(dev·prod) 필터

## 한 일

- 로그를 보여주는 모든 화면에 환경 필터(`전체` · `개발 (dev)` · `운영 (prod)`)를 달았다: 대시보드,
  LangFuse 로그 수집(저장된 로그 부분), Task 리뷰·채점, 채점 결과, 개선책(생성 탭), 개선 history,
  테스트 데이터(로그 input 탭).
- 공통 위젯은 `app/ui/env_filter.py`, 거르는 판단은 `environments.keep()` 하나로 모았다.
- 지금까지의 규칙("목록 자체를 환경으로 필터링하지 않는다")을 사용자 요청으로 바꿨다. 목록은
  여전히 한 목록이고, 필터 기본값은 `전체`다. knowledge(`langfuse-environments.md`)를 같이 고쳤다.

## 결정과 근거

- **한 번 고르면 모든 화면이 같은 범위를 본다.** 화면마다 따로 고르게 하면 대시보드는 운영, 채점
  결과는 전체처럼 범위가 어긋나 숫자를 비교할 때 헷갈린다. Streamlit 1.61의
  `segmented_control(..., key="env_filter", persist_state="session")`로 페이지를 옮겨도 선택이
  남는다. 브라우저에서 대시보드에서 운영을 고른 뒤 Task 리뷰로 옮겨 `운영 (prod)`이
  `aria-checked=true`인 것을 확인했다.
- 다중 선택 대신 `전체/개발/운영` 단일 선택 + `required=True`. 환경이 둘뿐이라 다중 선택은 "둘 다 /
  하나"와 같고, 빈 선택(아무것도 안 보임)이라는 쓸모없는 상태만 생긴다.
- 필터는 보기만 좁힌다. 동기화 버튼·환경별 수집 현황은 수집의 일이라 늘 모든 환경을 다룬다.
  개선책 반영 상태 탭은 개선책이 환경에 속하지 않아 거르지 않는다.
- 행 선택으로 상세를 여는 표(Task 리뷰, 채점 결과 Task 목록)는 필터 값을 key 에 넣었다. 선택이
  행 위치로 돌아오므로 필터가 바뀐 뒤 옛 위치가 엉뚱한 행을 열지 않게 한다. Task 리뷰의 "채점
  대상만 보기"도 같은 문제가 있어 함께 key 에 넣었다.
- 한 환경만 볼 때는 환경별 건수 metric 이 전체 건수와 같아 숨긴다.

## 검증

- `environments.keep`·`envs_for`·`scope_label` 테스트 3개 추가, 전체 unittest 187개 통과.
- 브라우저(streamlit 재시작 후): 대시보드 전체 19,481건(dev 19,461 · prod 20) → 운영 선택 시
  20건·비용 0.328로 바뀜. 페이지 이동 후에도 운영 유지(Task 리뷰 20건 / 수집 20건). 채점 결과는
  운영 채점 이력이 없어 빈 안내, 전체로 돌리면 Task 목록 복귀. 로그 수집·개선책·테스트 데이터
  화면에 필터 표시·오류 없음. 서버 로그 오류 없음.

## 막힌 점 / 열린 질문

- 개선 history 는 로컬 데이터에 반영된 개선책이 없어 필터 적용 경로를 화면으로는 확인하지 못했다
  (반영된 개선책이 있을 때만 필터가 보인다).
- 같은 시각 다른 세션이 `Dev 환경 테스트` 페이지를 추가 중이었다. 그 페이지는 이 작업 범위 밖이라
  건드리지 않았다.
