# 2026-08-28 — LangFuse 개발·운영 로그를 한 목록으로

계획: [.agents/plan/2026-08-28-dev-prod-로그-합쳐보기.md](../plan/2026-08-28-dev-prod-로그-합쳐보기.md)

## 배경

LangFuse 저장소가 두 개(개발·운영)로 분리됐다. 기존 코드는 키 한 벌로 클라이언트를 하나만
만들고(`langfuse_client.get_client` 가 인자 없는 `lru_cache`), 커서도 하나였다. `.env` 를
바꿔치기하는 방식으로는 커서가 서로를 밀어내 양쪽 다 구멍이 생긴다.

## 방향 전환 (중요)

처음에는 **환경별로 저장 폴더를 나누는** 쪽으로 구현했다(`data/dev/`·`data/prod/`, 사이드바
환경 선택기, 경로 함수마다 `env` 인자, 활성 환경 `ContextVar`). 사용자가 "분리하지 말고 합쳐서
시간순으로 정렬하되 dev/prod 만 알 수 있게" 를 원한다고 알려와서 방향을 바꿨다.

바꾼 뒤 실제로 없어진 것:

- `data/<환경>/` 계층과 경로 함수의 `env` 인자 → 원래 평면 구조로 되돌림.
- 활성 환경 `ContextVar`(`environments.use/active/resolve`) → 필요 없음. 환경은 항상 명시적으로
  넘기거나 행에서 읽는다.
- `app/storage/migrate.py`(예전 배치 이동) → 옮길 게 없어져서 삭제.
- 사이드바 환경 선택기 → 화면을 가르지 않으므로 고를 것이 없다.

남은 것은 **행에 붙는 `env` 하나**와, 환경이 실제로 갈리는 세 자리(자격증명·클라이언트·커서)다.
결과적으로 코드도 더 작아졌다.

## 한 것

- `app/environments.py` 신규 — 환경 키(`dev`/`prod`)·라벨·`of(record)`.
- `app/config.py` — `LangfuseCredentials` 와 환경별 키 해석. 어떤 변수 이름이 어떤 환경으로
  가는지는 `Settings.langfuse_credentials` 안의 표 하나로 모았다.
- `app/langfuse_client.py` — 환경별 클라이언트, 조회 함수에 `env` **필수**.
- `app/collect/sync.py` — 행에 `env`, 커서를 환경별 map(`{"dev": …, "prod": …}`)으로,
  `sync(env)` 와 `sync_all(envs)`. `SyncResult` 에 `environment`·`stored_total` 추가.
- `app/collect/generations.py` — `fetch_missing` 이 `(traceId, env)` 쌍을 받는다.
- 화면: 로그 수집(설정된 환경 전부 수집 + 환경별 현황 표) · 대시보드(환경별 건수) ·
  Task 리뷰(행의 env 로 상세 조회, 채점 결과에 env 저장) · 채점 결과(env 열) ·
  개선 history(결과 표 `환경` 열, 행별 env 로 모델·토큰 조회) · 테스트 데이터(행의 env 로 조회).
- 테스트 51개 통과(`test_environments` 10개 신규, `test_collection_sync` 에 합침·커서 독립 5개 추가).

## 결정과 근거

- **폴더 대신 행의 `env`.** 트레이스 id(32자리 hex)와 taskId(UUIDv7)가 전역 유일이라 파일명이
  부딪히지 않는다. 실제 수집 데이터에서 taskId 99개가 전부 UUIDv7 인 것을 확인하고 정했다.
  폴더를 나누면 목록을 보여줄 때마다 두 곳을 읽어 합쳐야 하는데, 화면이 원하는 건 어차피
  합친 목록 하나다.
- **커서만은 환경별.** 여기만은 합칠 수 없다. `sync(env)` 는 그 환경만 훑고 그 환경 커서만
  옮기며, 다른 환경의 행도 커서도 건드리지 않는다. 회귀 테스트로 고정했다.
- **`env` 기본값을 두지 않았다.** 조회 함수가 환경을 안 받으면 조용히 개발 프로젝트를 보게 되고,
  그건 운영을 본다고 착각하기 딱 좋다. 대신 저장된 데이터에는 `environments.of()` 로 관대하게
  읽는다(`env` 없으면 `dev` — 환경 구분이 생기기 전 데이터).
- **접두사 없는 예전 이름을 dev fallback 으로만 남겼다.** prod 에도 fallback 을 주면 운영 키를
  안 넣은 상태에서 개발 프로젝트를 운영이라고 믿고 보게 된다. 조용히 틀리는 것보다 "키 없음"
  으로 막는 쪽이 낫다.
- **`host` 는 공통으로 떨어지게 했다.** 두 프로젝트가 같은 Langfuse 인스턴스에 있는 게 흔한
  구성이라, 그 경우 `.env` 에 더할 줄이 키 2줄뿐이다.
- **SDK 가 클라이언트 2개를 버티는지 먼저 확인했다.** `langfuse/_client/resource_manager.py` 의
  `LangfuseResourceManager._instances` 가 public key 로 키를 잡는다. public key 가 다른
  클라이언트는 리소스를 공유하지 않고 동시에 살아 있어도 된다.
- **클라이언트 캐시를 `lru_cache` 대신 `dict[str, Langfuse]` 로 바꿨다.** 키를 인자로 받는
  `lru_cache` 를 쓰면 평문 키가 캐시 key 로 모듈에 남는다. 환경 문자열만 key 로 쓴다.

## 막힌 것 — Streamlit 사이드바

방향 전환 전, 사이드바에 환경 선택기를 넣었더니 **내비게이션이 사이드바째 사라졌다.**
`st.sidebar.*` 를 `st.navigation()` **앞에서** 호출한 게 원인이었다(사이드바 DOM 자체가 만들어지지
않는다). `st.navigation()` 으로 객체를 받은 뒤 사이드바를 그리고 마지막에 `.run()` 하면 정상이다.
지금은 선택기를 없앴지만, 앞으로 사이드바에 무언가 넣을 때 같은 함정이 있다.

## 데이터 정리

작업 중 잠깐 `data/dev/` 로 옮겼던 파일을 원래 위치로 되돌렸고, 기존 13,018행에 `env: "dev"` 를
채웠다. `collection.state.json` 은 평면 모양에서 `{"dev": {…}}` 로 바꿨다(코드도 평면 모양을
`dev` 로 읽어주므로 이 변환 없이도 동작한다).

## 남은 것

- prod 키를 `.env` 에 넣은 뒤 첫 수집은 전체 backfill 이다(그 환경의 커서가 아직 없다).
- 개선책 반영 시기(`appliedAt`)는 환경 구분 없이 하나다. 개발과 운영에 반영한 시점이 다르면
  개선 history 의 전후 비교가 한쪽 기준이 된다. 필요해지면 그때 환경별 반영 시기를 도입한다.
